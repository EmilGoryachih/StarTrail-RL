# StarTrail-AI Backend — RL-рекомендации поверх семантического поиска

## Краткий контекст системы
- **Фреймворк:** FastAPI, Python 3.11.
- **Поиск:** семантический (SentenceTransformers LaBSE) + FAISS IVF-PQ индекс.
- **Рекомендации:** гибрид — семантический пул кандидатов → RL-рерэнк (UCB) с учётом пользовательского фидбека.
- **Хранилище:** Postgres (async SQLAlchemy).
- **Auth:** JWT + refresh.

## Семантический слой (откуда берутся кандидаты)
1) Запрос пользователя кодируется LaBSE (`SentenceTransformer("sentence-transformers/LaBSE", device=cpu)`).
2) Поиск по FAISS IVF-PQ индексу (`Model/Indexes/poi_ivfpq.index`, nlist=128, nprobe=50, expand_k=1000) по эмбеддингам POI.
3) Фильтры: город, теги интересов (OSM-теги из `app/config/interest_tags.py`), исключение алкоголя если не запрошен.
4) Возвращается список POI (id, name, type, city, lat, lon, score, description).

Этот слой отвечает только за «смысловое сходство» и базовые фильтры. Он не «учится» на откликах пользователя.

## Что добавляет RL
RL не ищет новые точки сам; он переупорядочивает уже найденных семантикой кандидатов, балансируя между:
- **Exploit** — показывать то, что уже приносило высокую награду конкретному пользователю.
- **Explore** — давать шанс новым/неизведанным объектам.

### Какие данные хранит RL
Таблица `rl_interactions`:
- `id (uuid)`
- `user_id`
- `poi_id`
- `reward` (float; позитив/негатив)
- `created_at`

Через API `/api/rl/feedback` фронт отправляет награды (лайк/дизлайк/сохранение и т.п.), они пишутся в `rl_interactions`.

### Алгоритм ранжирования (UCB)
1) Берём расширенный пул кандидатов от семантики (например, limit*5, минимум 20).
2) Считаем статистику по пользователю: для каждого `poi_id` — количество показов/откликов и сумму наград.
3) Для каждого кандидата вычисляем Upper Confidence Bound:
   - Если пользователь этот POI не видел → UCB = +inf (это exploration).
   - Если видел → `avg_reward + exploration_coef * sqrt(log(total_interactions) / count)`.
4) Сортируем по UCB по убыванию, возвращаем топ-N.

Текущая реализация — лёгкий bandit-подход (UCB) без нейронок, но она демонстрирует online-learning: каждое действие пользователя сразу влияет на порядок выдачи.

### API для RL
- `GET /api/rl/recommendations?limit=10` — вернуть список POI, рерэнкованный RL.
- `POST /api/rl/feedback` — принять `{ "poi_id": "...", "reward": float }`, записать в `rl_interactions`.

### Как интегрировано в существующий код
- Семантический поиск и рекомендации по интересам остаются в `POIService`.
- `RLService` оборачивает `POIService`: получает пул кандидатов и рерэнкует.
- `RLRouter` подключён в `/api/rl` (см. `app/api/main.py`).
- Фидбек фронта можно слать при лайке/дизлайке/сохранении; сейчас пример — при добавлении в избранное отправляется `reward = +1`.

### Поток end-to-end
1) Пользователь авторизован (JWT).
2) Фронт вызывает `GET /api/rl/recommendations`.
3) Бэкенд:
   - Семантика даёт пул кандидатов.
   - RLService рерэнкует по UCB с учётом истории наград пользователя.
   - Возвращает топ-N.
4) Пользователь взаимодействует (лайк/дизлайк/сохранение) → фронт шлёт `POST /api/rl/feedback`.
5) Запись попадает в `rl_interactions`; следующий запрос рекомендаций учитывает обновлённую статистику.

## Данные и параметры
- Индекс: `Model/Indexes/poi_ivfpq.index` (IVF-PQ, nlist=128, nprobe=50, expand_k=1000).
- Метаданные POI: `Model/Dataset/poi_dataset_enriched_incremental.csv`.
- RL exploration коэффициент: `exploration=1.2` (в `RLService`).
- Пул кандидатов для рерэнка: `max(limit*5, 20)`.

## Компоненты кода (важные файлы)
- `app/services/POIService.py` — семантический поиск и базовые рекомендации по интересам.
- `app/services/RLService.py` — логика UCB-рерэнка и запись фидбека.
- `app/api/routes/RLRouter.py` — эндпоинты `/api/rl/*`.
- `app/models/dbModels/RLInteraction.py` — ORM-модель фидбека.
- `app/infrastructure/repositories/RLInteractionRepository.py` — запись/агрегация фидбека.
- `app/config/interest_tags.py` — маппинг интересов → OSM-теги (для фильтрации кандидатов).

## Что видеть пользователю / как демонстрировать RL
- Вызовы `/api/rl/recommendations` меняют порядок выдачи после фидбека.
- Новые объекты (без истории) имеют высокий UCB → exploration.
- Объекты с положительным reward поднимаются выше (exploit).

## Быстрый FAQ
**RL сам ищет объекты?** Нет. Он переупорядочивает кандидатов, найденных семантикой.  
**Откуда берутся награды?** Из пользовательских действий (лайк/дизлайк/сохранение и т.п.), которые фронт шлёт на `/api/rl/feedback`.  
**Что обучается?** Статистика наград по пользователю и UCB-рерэнк (bandit). Каждое действие сразу влияет на порядок.  
**Можно ли без RL?** Да: используйте `/api/poi/recommendations` — это чистый семантический подбор по интересам.  
**Как быстро показать результат?** Дать пару фидбеков (+/-), вызвать `/api/rl/recommendations` снова и увидеть смену порядка (explore/exploit).
